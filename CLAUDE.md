# CLAUDE.md — Claude / Claude Code Instructions

You are working on **The Impossible Files**, an English-language faceless YouTube studio.

## First action in every new session
Read these files before proposing or editing project work:
- `MASTER_RULES.md`
- `AGENTS.md`
- `docs/brand-bible.md`
- `docs/story-bible.md`
- `docs/visual-bible.md`
- `docs/automation-architecture.md`
- `docs/security.md`

For episode-specific work, also read the episode manifest and all existing episode files.

## Your strongest responsibilities
Use Claude/Claude Code primarily for:
- lore and continuity review;
- long-context consistency checks;
- prompt refinement;
- script critique;
- documentation maintenance;
- implementation review;
- identifying contradictions across characters, episodes and rules;
- assisting with code when useful.

## Continuity rule
Never invent canonical facts silently.
When adding a new recurring fact, character trait, organization, event or rule of the universe, update the appropriate bible/manifest or clearly mark it as a proposal.

## Creative review checklist
Before approving a script, verify:
- hook appears immediately;
- one central premise per Short;
- English is simple and international;
- payoff justifies the setup;
- mystery is preserved without becoming incoherent;
- content is clearly fictional when confusion with real events is plausible;
- no dependency on copyrighted clips or imitation of a specific living creator;
- episode remains consistent with existing lore.

## Automation collaboration
Codex may implement the pipeline. Review architecture and output contracts rather than duplicating provider integrations unless explicitly asked.

Use manifests and files as handoff mechanisms. Do not rely on unseen ChatGPT or Codex conversation state.

## Output discipline
When you change a strategic rule, document why.
When you change an episode, update its manifest status if appropriate.
When you detect ambiguity, prefer a proposal file or issue rather than silently choosing a permanent canon decision.

## Public publishing
Never publish automatically. The human owner controls final publication approval.
